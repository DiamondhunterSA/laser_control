IMPORTANT:
  * Release 3.1.0 and later may not work in linux with older compiler (glibc-2.28 (and below), g++6). If an older system needs to use the latest OceanDirect
    then the recommended solution is to either upgrade the compiler to the latest version or upgrade the system to a newer version with latest compiler.
  * Release 2.0.0 requires a FW upgrade for all OBP2 enabled devices in order to fully utilize the command query functionality.
    -if you don't do this then some feature might be disabled. The work around is to revert back to 1.33.0 version.
    -this version will not impact older units.

Pending Issues:
  * Reimplementation of time, stray-light, and raw bus features for new OBP2 architectures needs further testing
  * While your program is continuosly reading spectra, DO NOT kill your program or put your
    computer into sleep/hibernate mode as doing so will will result in failure at openDevice()
    call on the 2nd run. This is due to the device responded with different command code. The
    only remedy for now is to unpower and repower back the unit.
  * FX will get stuck when you read raw spectra with metadata at some point after you disable data buffering. The solution
    for now is to leave the data buffering on.
  * FX/HDX network connected units after reset device will return a reset-device command code for commands such as get serial number, get wavelength
    coefficients, etc. This is a FW bug.
  * FX/HDX delete static ip address starts at index 1 instead of 0.
  * Shutter function is only implemented for OceanNR.
  * MayaPro has FW issue. The get_trigger_mode() function always returned 0. We dont have this issue with Flame-S which has
    the same command and input.
  * NIRQuest has a FW issue. The function get_continuous_strobe_period() returns bad value. This issue 
    could be related to set_continuous_strobe_period(). The set_continuous_strobe_period_width() has issue with this unit.
  * Dynamic device probing support for ethernet comm feature on new spectrometer only worked in Windows. There is still issue with mac and linux.
    
Usage Requirements:
  * GPIO set/get data command usage on NIRQuest256, USB4000, MayaPro, Flame-T and HR2000+ES (and probably some other units I missed). 
    -you must call the alternate function first and set it to GPIO pin in order for the set/get data command to work.

Python Requirements:
  Need at least version 3.9.5
